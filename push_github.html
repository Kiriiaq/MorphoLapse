2. Checklist pré-push

  • Tests verts : make test ou python -m pytest tests/smoke tests/functional -q → 102 passed attendu
  • Lint propre : make lint ou python -m ruff check . → All checks passed
  • Smoke build : python build.py debug --onedir → EXIT 0
  • Identité git configurée : git config user.email et git config user.name
  • Authentification GitHub prête (PAT ou clé SSH ajoutée à ~/.ssh/)
  • (optionnel) Décider du sort de AUDIT.txt et PLAN.txt — livrables transitoires
  • (optionnel) Tag de version v2.1.0 si tu veux déclencher une release CI
Recommandation : les fichiers AUDIT.txt et PLAN.txt sont des livrables des phases 1 et 2 de la réorg. Ils sont utiles pour la traçabilité du commit de réorganisation, puis peuvent être supprimés au commit suivant. Décision : on les commit dans chore: audit puis on les supprime dans un commit chore: drop audit artifacts après merge, OU on les laisse versionnés à vie pour historique.

3. Procédure de push (commits atomiques)

1

Commit du livrable d'audit (AUDIT.txt + PLAN.txt)

git add AUDIT.txt PLAN.txt
git commit -m "chore: audit (Phase 1 + Phase 2 deliverables)"

Documente l'analyse initiale et le plan validé avant exécution. Permet de retracer les décisions a posteriori.

2

Commit du rename test/ → qa/

git add qa/
git commit -m "refactor: rename test/ to qa/ to disambiguate from tests/"

Seul changement structurel : la campagne QA manuelle a son dossier dédié, ne se confond plus avec la suite pytest.

3

Commit de la consolidation documentaire

git add README.md CHANGELOG.md
git add -u BASELINE_TESTS.md BUILD_REPORT.md DIAGNOSTIC.md \
    RAPPORT_PHASE_A.md RAPPORT_PHASE_B.md RAPPORT_PHASE_F.md \
    RELEASE_2.0.0.md audit/
git add src/ui/main_window.py src/ui/widgets.py
git commit -m "chore: consolidate docs (new README + CHANGELOG, purge 15 historical .md)"

Le flag -u sur git add stage les suppressions des fichiers .md historiques. Les 2 modifs src/ui/*.py sont les commentaires "see DIAGNOSTIC.md" → "see CHANGELOG.md".

4

Commit du nettoyage des artefacts

git add -u INVENTAIRE.csv
git commit -m "chore: cleanup stale artifacts (INVENTAIRE.csv, coverage HTML)"

Les logs/*.log, tests/runs/coverage_v2/, .coverage, __pycache__/ sont déjà gitignored donc absents de l'index — pas besoin de les staged.

5

Commit des correctifs accumulés (Lots J-N, FFmpeg, AZERTY, CPU, etc.)

Si tu préfères des commits plus granulaires, segmente plutôt en plusieurs git add <fichier> ; git commit -m "..." ciblés.

6

Vérification finale avant push

git status                  # doit afficher : nothing to commit, working tree clean
git log --oneline -10        # vérifier les 5 nouveaux commits en tête
git diff origin/main..HEAD --stat   # récap des changements vs remote
7

Push vers origin/main

git push origin main
Authentification : GitHub n'accepte plus le mot de passe pour HTTPS depuis août 2021. Utiliser un Personal Access Token (PAT) (Settings → Developer settings → Personal access tokens → Tokens (classic)), ou switcher en SSH via git remote set-url origin git@github.com:Kiriiaq/MorphoLapse.git après avoir ajouté ta clé publique aux SSH keys GitHub.

4. Créer une release v2.1.0 (optionnel mais recommandé)

Le workflow CI .github/workflows/release.yml se déclenche sur les tags v* et produit automatiquement les EXE Windows + une release GitHub avec les binaires attachés.

Étapes

# 1. Annoter le tag
git tag -a v2.1.0 -m "v2.1.0 — UI polish + FFmpeg robustness + reorganisation"

# 2. Pousser le tag (déclenche release.yml automatiquement)
git push origin v2.1.0

# 3. Suivre le build dans l'onglet Actions sur GitHub
#    https://github.com/Kiriiaq/MorphoLapse/actions
Préparer les notes de release : ouvrir https://github.com/Kiriiaq/MorphoLapse/releases/new?tag=v2.1.0 une fois le workflow vert. Copier-coller la section "Unreleased" de CHANGELOG.md comme corps de la release puis la renommer en "[2.1.0] — 2026-05-27" dans le CHANGELOG (commit suivant).

5. Vérifications post-push

  • L'onglet Actions de GitHub montre le run ci.yml en cours puis ✓
  • L'arbre du repo sur GitHub reflète le nouveau README.md rendu
  • Le lien vers CHANGELOG.md depuis le README fonctionne
  • Le dossier qa/ apparaît (et plus de test/)
  • Les fichiers audit/*.md, BASELINE_TESTS.md, BUILD_REPORT.md, DIAGNOSTIC.md, RAPPORT_PHASE_*.md, RELEASE_2.0.0.md, INVENTAIRE.csv ne sont PAS dans le repo public
  • Si tag pushed : la release apparaît avec les EXE attachés sous quelques minutes
  • Le badge Python/MIT/Platform du README s'affiche correctement

Symptôme Cause probable Résolution
! [rejected] main → main (non-fast-forward) Quelqu'un (ou un CI) a poussé sur origin/main entre-temps git pull --rebase origin main puis git push origin main

error: src refspec main does not match any Pas de commit sur la branche locale, ou branche mal nommée git branch --show-current ; git log --oneline
