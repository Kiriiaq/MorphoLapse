3. DOUBLONS / DOSSIERS À NOM SYNONYME
--------------------------------------------------------------------------------
CRITIQUE : `test/` ET `tests/` coexistent à la racine — sens différents, pas
un vrai doublon mais nommage prêtant à confusion :
  - `tests/` : suite pytest (114 tests, pyproject.toml > testpaths = ["tests"])
  - `test/` : campagne QA manuelle (matrice Excel, HTML interactif, datasets
    PNG synthétiques, rapport)
  → Renommer `test/` en `qa/` ou `qualification/` éliminerait toute ambiguïté.

PAS DE DOUBLON sur les autres conventions classiques (doc/docs, util/utils,
script/scripts, asset/assets) : tout est déjà au pluriel et cohérent.

8. RÉFÉRENCES CROISÉES — risque pour Phase 4 (réorganisation)
--------------------------------------------------------------------------------
Si on déplace les sources vers `src/morpholapse/` (layout PEP 561 strict),
il faudra mettre à jour :

  Code Python (28 fichiers concernés)
    src/**/*.py : remplacer `from ..` / `from .` → relatifs préservés (OK)
                  mais les ré-exports dans `src/__init__.py` (`__version__`)
                  et l'import `from .. import __version__ as MORPHOLAPSE_VERSION`
                  doivent rester cohérents.
    main.py : `from src.ui.main_window import run_app` →
              `from morpholapse.ui.main_window import run_app`
    main.py : `from src.modules.* import ...` →
              `from morpholapse.modules.* import ...`
    tests/**/*.py : 59 imports en `from src.xxx` →
                    `from morpholapse.xxx`

  Build/packaging
    pyproject.toml :
      [project.scripts] morpholapse = "main:main"
        → potentiellement `morpholapse = "morpholapse.__main__:main"` si on
          déplace main.py dans le package, ou rester `main:main` si on garde
          main.py à la racine.
      [tool.setuptools.packages.find] where = ["."] include = ["src*"]
        → where = ["src"], include = ["morpholapse*"]
      [tool.setuptools] py-modules = ["main"]
        → à retirer ou à adapter selon choix ci-dessus.
      [tool.ruff] src = ["src", "tests"] → src = ["src/morpholapse", "tests"]
      [tool.pytest.ini_options] testpaths = ["tests"] → inchangé.

    build.py :
      "--add-data" "src;src" → "--add-data" "src/morpholapse;morpholapse"
      Tous les `--hidden-import` et `--collect-all` à revérifier.
      paths.py utilise `sys._MEIPASS / "assets" / ...` ce qui reste valide.

    Makefile :
      mypy `src` → mypy `src/morpholapse`
      coverage `--cov=src` → `--cov=morpholapse`

    .github/workflows/release.yml : références à `main.py` et `src/`
      à actualiser.

  Documentation .md
    Quasiment toutes les références dans audit/, RAPPORT_*.md, BASELINE_TESTS,
    DIAGNOSTIC, BUILD_REPORT, test/* pointent sur des fichiers `src/...`.
    Si rename : ces .md ne sont pas le code, mais devront mentionner le
    nouveau chemin pour rester lisibles. Comme la Phase 3 prévoit de tout
    fusionner dans README.md de toute façon, c'est un non-problème — seul
    le bloc « Structure du projet » du nouveau README doit refléter la
    cible.

  Tests qui hard-code des chemins
    tests/conftest.py et tests/functional/test_paths.py utilisent
    `from src.utils import paths` et inspectent `paths.get_resource_root()`.
    → mise à jour mécanique de l'import suffit.
    test/scripts/run_tests.py et generate_inputs.py utilisent des chemins
    relatifs au cwd (`test/inputs/...`) — pas impactés par un rename de src.

  Importé par le viewer HTML / preview
    Aucun (le HTML est statique, pas de référence Python).
